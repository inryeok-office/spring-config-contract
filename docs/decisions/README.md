# Architecture Decision Records

Architecture Decision Records (ADRs) document decisions that affect the structure, constraints, or long-term direction of the project. Add a numbered Markdown file when a decision is meaningful, durable, and useful to future contributors.

Use a concise title, record the context and decision, and explain consequences. Update an ADR rather than silently changing a settled decision; supersede it with a new ADR when appropriate.

## Template

```markdown
# ADR-NNNN: Decision title

- Status: Proposed | Accepted | Superseded | Deprecated
- Date: YYYY-MM-DD

## Context

What problem or constraint led to this decision?

## Decision

What was decided, and what boundaries does it establish?

## Consequences

What benefits, trade-offs, and follow-up work result?
```
